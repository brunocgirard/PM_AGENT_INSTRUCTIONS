PLANNER STATUS REPORT PROMPT - Weekly Update
Version 2.0 - 2026-05-29
Use in: Teams desktop > Planner > your Premium plan > Reports tab > Get Started.
  1. Pick the reporting period (this week) in the dropdown.
  2. Fill the [AUDIENCE] / [REPORTING PERIOD] / [SPONSOR] placeholders below.
  3. Copy EVERYTHING BELOW THE LINE into the "Provide more details" box.
  4. Generate, then REVIEW the draft before sharing - the AI can misframe data.
v2 note: the Planner Agent imposes its own top-level sections, so this prompt
no longer numbers sections. It leads with a colored "Status at a Glance" table
(the visual anchor) and enforces density so the result reads professionally.

----------------------- PASTE BELOW THIS LINE -----------------------

You are a senior project manager writing a WEEKLY status update for [AUDIENCE - e.g. "the executive sponsor and delivery lead"] about this Planner plan, for the period [REPORTING PERIOD - e.g. "week of 26-30 May 2026"].

GOAL: an executive can grasp the entire status in under 60 seconds. The report must be visual, dense, and scannable - a dashboard, not a wall of text.

DATA RULES:
- Use ONLY this plan's data: task names, due dates, % complete, assignments, priority (Urgent/Important/Medium/Low), milestones, dependencies and critical path if present, and overdue items.
- NEVER invent dates, owners, or status. If something is not in the plan, write "Not available in plan".
- Count something as accomplished only if the task was completed WITHIN [REPORTING PERIOD]. If there were no completions, say that in the Summary sentence - do not create an empty section for it.
- Ignore any earlier conversation; base the report only on the current plan.

PRESENTATION RULES (this is what makes it executive-friendly - follow exactly):
- Begin with the project name as a single short title line, then IMMEDIATELY a "Status at a Glance" table. Make this table the visual anchor of the whole report.
- The Status at a Glance table has exactly these columns: | Area | Status | Note (max 8 words) |. Rows in this order: Overall, Schedule, Scope, Resources, Risk. In the Status cell put a colored dot AND the word together: "🟢 On track", "🟡 At risk", "🔴 Off track", or "⬜ N/A". (The dot+word is self-explanatory - do NOT add a separate RAG legend block.)
- Use short ONE-LINE bullets. Bold the key number or name in each bullet, e.g. "**8 tasks** overdue" or "**UAT** starts Mon".
- Prefer tables and tight bullets over paragraphs. Never write a paragraph where a bullet or table cell will do.
- DENSITY: keep the whole report to roughly one screen. Do NOT pad. If a section has no content, OMIT that section entirely - never insert placeholder lines like "No items this period".
- Do NOT number the headings. Do NOT insert horizontal divider lines. Do NOT add sections beyond those listed below.

CONTENT - use these short headings, in this order, and include a heading ONLY if it has real content (Status at a Glance and Summary are always included):

Status at a Glance
- The colored scorecard table described above.

Summary
- 1-2 sentences in plain language: the headline of the week and the single biggest concern. State here if there were no completions.

Progress This Week
- One-line bullets of tasks or milestones completed within [REPORTING PERIOD], highest priority first.

Plan Next Week
- One-line bullets of tasks due or starting next week, Urgent/Important first.

Risks & Blockers
- A table with exactly these columns: | Item | Impact | Owner | Next action |. Top items only (max 5). Owner is the task assignee, else "Unassigned".

Decisions Needed
- One line each: what is needed - from whom ([SPONSOR] or the role in the plan) - by when.

TONE: professional, direct, factual. No filler phrases ("it is worth noting", "as we move forward"), no praise, no hedging.

This report is a DRAFT for the project manager to review and correct before distribution.
